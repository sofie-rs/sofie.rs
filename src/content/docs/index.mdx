## A few lines, a whole feature

An action that adds a product, a query that lists products, and the routes that serve them:

```rust
#[derive(Input)]
pub struct AddProduct {
    name: String,
    price: Money,
}

pub async fn add_product(input: AddProduct) -> Result<Product> {
    Product::new(input.name, input.price)
}

pub async fn list_products(read: Read) -> Result<Vec<ProductRow>> {
    ProductRow::query().latest().limit(50).all(&read).await
}

pub fn routes(routes: &mut Routes<Web>) {
    routes.screen("/products", "products", queries::list_products);
    routes.post("/products", actions::add_product).then_screen("products", "products");
}
```

```html
<Section title="Products">
  <Form id="add-product" post="/products" target="products">
    <Submit label="Add product" />
  </Form>
  <Table id="products" of={data} columns="name price" />
</Section>
```

From this, sofie serves a page whose form is built from `AddProduct`, a table that updates in
place, the same rows as JSON at the same URL, field-by-field validation errors, CSRF protection
and a trace per request. `sofie explain` and `sofie mcp` answer questions about any route.
[Build it yourself in ten minutes](start/first-page/).

## What comes with it

<CardGrid>
	<Card title="Server-driven UI" icon="laptop">
		One template format rendered on the server and updated over htmx, with Svelte islands where
		a page needs rich interaction.
	</Card>
	<Card title="One database" icon="setting">
		Postgres or SQLite holds the records and also the event outbox, jobs, schedules and cache.
		Redis and Meilisearch are optional.
	</Card>
	<Card title="Accounts and SaaS" icon="seti:lock">
		Sign-up, passkeys, OAuth, two-factor, impersonation, organizations, billing with Stripe or
		Paddle, mail, notifications and feature flags, as packages.
	</Card>
	<Card title="Made for coding agents" icon="puzzle">
		A generated `AGENTS.md` and an MCP server over the same app model, so an agent finds where
		code goes and what it may touch.
	</Card>
</CardGrid>
